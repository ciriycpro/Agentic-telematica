# «Цифровой диспетчер» — краткое решение
## Пересборка легаси-телематики разъездных сотрудников в агентную решающую систему для мобильного оператора

---

### 1. Резюме для руководства

**Что предлагается.** Превратить телематическую платформу оператора из учётной системы в решающую: сегодня платформа показывает данные, а все решения принимает человек — завтра она сама классифицирует события, действует в пределах строго заданных полномочий и зовёт человека там, где не имеет права или не уверена. Продаётся как надбавка к действующему тарифу; строится один раз как общий контур на стороне оператора для всех 10 500 компаний базы.

**Как устроено.** Поток телеметрии обрабатывают детерминированные правила, как и сейчас — нейросеть его не видит. Правила рождают события («подозрение на слив», «задача без исполнителя»). Дальше языковая модель принимает решение сама — но строго из заранее прописанного меню вариантов (звонок, SMS, переназначение, эскалация) и с учётом текстового регламента конкретного клиента; если уверенности нет или класс действия не её — решение уходит человеку. Необратимое (кадровые и юридические выводы, конфликтные переназначения) не автоматизируется никогда. Полномочия автоматики расширяются по измеренной точности (80% для внутренних действий, 95% для контактов с человеком), а не по календарю; сотрудник получает канал оспаривания любого действия с любого телефона.

**Что получает клиент** (профиль: 300 сотрудников, 100 машин): реакция на инцидент за минуты вместо «завтра из отчёта»; диспетчер ведёт в 1,5–2 раза больший парк; клиенты компании получают время прибытия по SMS. Эффект ~1,5 млн ₽/год против цены 780 тыс. — **отдача +30…+92%, окупаемость 6–7 месяцев** (сценарий с ростом выручки до +346% существует, но независимо не подтверждён и в базу не входит).

**Что получает оператор:** операционная безубыточность — 32 компании (0,3% собственной базы), план с целевой прибылью — 65 (0,6%), возврат вложений ~4,8 млн ₽ за 24 месяца. Продажи — силами существующей корпоративной сети по тёплой базе.

**Риски: модель умеет быть отрицательной — и это её достоинство.** Переломы названы числом, у каждого дешёвая проверка ДО основных затрат: точность детекции ниже 71% убивает эффект (проверка — прогон на исторических данных клиента, в пределах текущего OpEx); доля GPS-оснащённых клиентов ниже 40% ломает средний чек (проверка — биллинговая выгрузка типов терминалов); превышение лимитов обзвона съедает прибыль целиком — поэтому бюджет беспокойства не этика, а условие выживания модели.

**Статус:** верифицировано отраслевым исследованием 40+ систем — архитектурное ядро совпадает с практикой лидеров, а **автономия по измеримым порогам доверия аналогов на рынке не имеет**; три внешних ревью (продакт, продажи, архитектор) пройдены; работающий прототип прилагается.

### 2. Проблема и карта болей

Текущий сервис — учётная система, а не решающая: данные собираются исправно, но между событием и реакцией стоит человек и сутки. Ключевые боли:

- **Диспетчер — узкое горлышко:** все назначения и разборы вручную; его пропускная способность ограничивает рост обслуживаемого парка.
- **Топливная петля разомкнута:** слив фиксируется датчиком уже сейчас — но становится строкой в завтрашнем отчёте, когда деньги утекли.
- **GSM-сегмент отрезан:** сотрудники с кнопочными телефонами вне цифрового контура — ни приложений, ни чатов.
- **Клиент заказчика в темноте:** ждёт бригаду «с 9 до 18», о срыве узнаёт постфактум — заказчик теряет клиентов.

### 3. Архитектура: пять принципов и честная граница LLM

**Поток одной строкой:** `Телематика → CEP-правила → ИИ-агенты в строгих рамках → каналы (голос/SMS/USSD) → человек`

**Пять принципов:**
1. **Детерминизм на потоке.** Поток координат и телеметрии считают жёсткие правила; LLM-инференс на нём не сжигается — это вопрос себестоимости.
2. **LLM решает только на событиях и только из меню.** Выбор строго из белого списка действий; недоступный инструмент отсутствует у агента физически, а не «запрещён промптом».
3. **Матрица полномочий с измеримыми порогами доверия.** Автономия открывается классу действий по накопленной статистике (80% внутренние / 95% + подтверждающий вопрос — контакты с человеком), а не по календарю; необратимое — человек всегда.
4. **LBS никогда не порождает автодействий.** Координата ±1 км — датчик низкого разрешения, а не доказательство: ложные претензии к людям исключены классом, а не настройкой.
5. **Канал апелляции.** Сотрудник оспаривает любое действие автоматики с любого телефона; спорный инцидент блокирует дальнейшие автодействия до человека-арбитра. Система получила право действовать в отношении человека — человек получил право остановить систему.

**Матрица полномочий в двух строках (полная — в основном документе):**

| Класс действия | Ф2 (стартовая) | Ф3 (открывается по метрике) |
|---|---|---|
| 1 — обратимые внутренние (карточка, задача, приоритизация) | авто | авто |
| 2 — контакт с человеком (SMS, звонок) | предлагает → человек | авто при precision ≥ 95% + подтверждающий вопрос |
| 3А — рутинные переназначения | предлагает с обоснованием | авто при precision ≥ 80% |
| 3Б — ситуативные переназначения / 4 — кадровые выводы | предлагает | **никогда не автоматизируется** |

Ключевое: **порог открытия автономии — измеримая точность на данных конкретного клиента**, не календарный срок. Класс 2 (контакт с человеком) держит более высокий порог, чем внутренние действия — цена ошибки выше.

**Что у оператора уже есть — и что добавляем мы.** Автораспределение заявок по правилам, автомаршруты и формы у оператора уже работают — наша новизна не в факте автоматизации. Добавляем: суждение LLM в неоднозначных событиях, измеримые пороги автономии, двусторонний голос на любом GSM, фильтр качества источника данных и замкнутую петлю «событие → решение → действие → результат» с апелляцией.

**Зачем здесь LLM — и где она не нужна.** Решения о деньгах и людях принимают правила и пороги — так спроектировано. LLM работает **переводчиком между миром людей и миром системы** в четырёх местах, где правила бессильны: свободная речь монтажника → поля акта; текстовый регламент заказчика → условия для решений (правила каждого из 10 500 клиентов не нужно программировать); вопрос диспетчера словами → ответ из данных за секунды; факты решения → понятная причина для человека (объяснимость измерима и входит в порог доверия).

**Эксплуатационный контур** (то, что видно только под нагрузкой): асинхронный инференс с приоритизацией по классу события; оркестратор долгоживущих сценариев с сохраняемым состоянием («ждём ответ водителя»); правила и пороги во внешнем конфиг-хранилище — калибровка клиента без перезапуска контура.

### 4. День из жизни

**Топливный кейс, вторник 14:02.** Датчик машины 47 фиксирует −40 л при выключенном двигателе. Вчера диспетчер узнал бы об этом завтра из отчёта. Теперь: в 14:03 система сама звонит водителю — автоинформатор, закрытый вопрос «подтвердите: заправка — да или нет?», верификация ответа; в 14:05 у диспетчера карточка: ответ распознан, не подтверждено, доказательная база собрана (трек + звонок + расшифровка), задача создана — вывод о человеке остаётся за человеком. Петля «событие → решение → звонок → результат» замкнулась за три минуты.

**Монтажник Сергей** наговаривает отчёт за 40 секунд в трубку вместо формы на морозе — система сама раскладывает речь в акт. **Владелец Алексей Петрович** перед планёркой видит на телефоне потери и эффект в рублях, а не точки на карте. **Клиент заказчика** получает SMS «мастер будет в 14:30» вместо окна «с 9 до 18» — впервые видит сервис вообще; окно ожидания сжимается, отток к конкурентам режется на входе.

### 5. Экономика: два уровня

**Клиент (300 сотрудников, 100 машин):**

| Показатель | Значение |
|---|---|
| Эффект (время диспетчера + топливо + SLA) | ~1,5 млн ₽/год |
| Цена тарифа «+решения» | 780 тыс. ₽/год |
| Отдача | **+30…+92%** (потенциал роста до +346% — не подтверждён, в базу не входит) |
| Окупаемость | **6–7 месяцев** |

**Оператор (единый мультитенантный контур):**

| Показатель | Значение |
|---|---|
| Операционная безубыточность | 32 компании (0,3% базы) |
| План с целевой прибылью | 65 компаний (0,6% базы) |
| Разовые вложения (CAPEX) | ~4,8 млн ₽, возврат за 24 мес |
| Продажи | 3–4 встречи/нед силами действующей сейлз-сети по тёплой базе |

**Стресс-тест:** переломы названы числом — точность < 71% (эффект клиента → 0), конверсия базы < 0,3% (операционный минус оператора), дорогой обзвон без лимитов (безубыточность взлетает до уровня плана продаж — прибыль исчезает), GPS-доля клиентов < 40% (ломается средний чек). Каждый перелом проверяется до основных затрат.
